# Status Quo requirements

Approved scope: `2026-11-01-status-quo-design.md` plus independent removable/interchangeable widgets. G: Giovanni; D: derived implementation promise. Tests carry `REQ SQ-*`; real-host acceptance supplements unit tests. No milestone approval pauses.

| ID | Requirement | Source |
|---|---|---|
| SQ-1 | Every data functionality is an independently removable, replaceable registered widget; an empty tray remains usable | G |
| SQ-2 | Independent instances retain separate settings, identity, order, size and detachment across restart | G |
| SQ-3 | Customize light/dark/system mode, colors, accent, font, background-only opacity and density; navigation-off preserves local controls; invalid imports preserve valid settings | G |
| SQ-4 | Deduplicate token history, preserve unavailable counters, reject regressions/overflow, retain 30 days and graph hourly/daily/cumulative values for 24h/7d/30d | G |
| SQ-5 | Show provider five-hour/weekly percentages used and resets selected by duration; missing limits are unavailable, never zero | G |
| SQ-6 | Read account status without model calls; timeouts/auth/rate-limit failures preserve last valid values and expose freshness | G |
| SQ-7 | Incremental transcript adapters handle partial/malformed files, rotation, cumulative counters and resets without silent loss or double counting | D |
| SQ-8 | Group main sessions by project with expandable subagents and explicit states; inactivity proves neither completion nor blockage | G |
| SQ-9 | Consume versioned lifecycle/progress events; hook installation preserves existing settings; unavailable evidence is explicit | G |
| SQ-10 | Selected GitHub repositories show commits, pull requests, issues, releases and checks with deduplication, bounded reads and visible access failures | G |
| SQ-11 | Read recent workflow-memory preferences, decisions, open/resolved items from both assistants with filters/timestamps and no writes; report malformed records | G |
| SQ-12 | Atomic versioned persistence rejects conflicting/invalid updates, preserves valid data and never stores credentials or conversations | D |
| SQ-13 | Per-user bounded local transport rejects incompatible versions and oversized requests; one collector serves independent hosts | D |
| SQ-14 | Core/contract/widget models have no GUI, filesystem, process or network dependencies; hosts/styles extend through registration | G |
| SQ-15 | KDE defaults behind windows, supports configurable stacking and retained geometry, recovers after monitor changes and exposes unsupported capabilities | G |
| SQ-16 | Actual rendering/actions honor save/cancel, reorder/resize, per-widget themes and add/remove/replace | G |
| SQ-17 | Configurable login startup and crash recovery cannot create duplicate collectors or erase another writer's state | D |
| SQ-18 | One failed source never freezes/hides unrelated widgets; loading/empty/unavailable/stale/error differ visibly | D |
| SQ-19 | Provider work is bounded and off the interface thread; backoff respects safe polling and local events display within two seconds | D |
| SQ-20 | Same widgets/tray render in another Rust host and browser sample without KDE imports or browser access to local credentials | G |
| SQ-21 | Presets/layout import/export are validated data-only; navigation uses safe schemes and argument-separated launches | G |
| SQ-22 | Linux integration checks actual X11/Wayland capabilities; portability claims identify evidence and fallbacks | G |
| SQ-23 | Laptop acceptance: under 1% of one core over five idle minutes, under 200 MiB collector+panel RSS and normal interaction within 100 ms | D |
| SQ-24 | No analytics, prompt transmission, generation or credential writes; diagnostics/history contain no complete conversations | G |
| SQ-25 | Verify installed package/startup/uninstall, template gate/CI and source-matched wiki translations | G |
| SQ-26 | A host compatibility layer chooses layer-shell, X11 desktop hints or a plain window at run time from the real session, honors a forced choice only when it can work, and reports what was chosen and why | G |
| SQ-27 | Layer-shell host shows the tray frameless on the desktop layer (below windows by default, anchored to an edge or corner, validated size), accepts pointer input, and costs no frames while idle | G |
| SQ-28 | Desktop-widget look: the tray itself has no background or title, only the widgets and the Add widget and Customize buttons are visible, and the widget rows fill the tray space exactly | G |
| SQ-29 | Edit tray: an Edit tray button turns the tray into a free canvas editor; every widget border and corner resizes on both axes to any size, the widget body moves it anywhere, widgets adapt their content to their size, the tray surface grows and shrinks with the widgets up to the whole desktop (the layer host covers the output while editing), one configurable space between widgets (Customize) is used by the flow layout, new widgets and the editor, borders and sizes dragged within 10 pixels of another widget stick to it (settling exactly one gap away or at the same size), Done saves through the validated configuration path, Cancel discards, a locked layout cannot be edited, widgets can be placed anywhere on the desktop (also left of and above the docked tray), and a Remove button in the centre of each widget removes it from the draft (Done saves, Cancel restores) | G |
| SQ-30 | System widget: CPU usage and temperature graphs from a read-only sampler (two small kernel files every 5 seconds, no process spawn), bounded 10-minute history kept in memory only, unreadable values shown as unavailable never zero, no sampling and no snapshot revision while no system widget exists | D |
| SQ-31 | Transcript discovery tolerates a projects folder with ~100,000 empty folders: empty folders never trip the discovery bound, only project folders holding recent transcripts are watched, and Claude token history keeps updating | D |
| SQ-32 | RAM and GPU widgets: RAM used/swap from `/proc/meminfo` with the CPU sampler; the GPU widget covers every GPU of any vendor (NVIDIA via `nvidia-smi`, AMD and others via sysfs, Intel via frequency and idle-residency counters); a GPU that is not the display adapter and has powered itself down is never woken to be measured (power state read from sysfs, measured only while something else keeps it awake, stopped once idle); asleep or unreadable values are unavailable, never zero | D |
| SQ-33 | Every widget measures the room left under its title and controls and fits it (charts split it, lists scroll); compact charts (system, RAM, GPU widgets) share the widget height without scrolling, follow it when the widget is resized on the y axis, use a fixed 0-100 range for percentages and a fitted range for temperature and clock, and have no timestamp or legend rows | G |
| SQ-34 | Edit tray: while a widget is dragged, a highlighted line shows every border, gap-spaced border or centre axis it lines up with and every equal width or height; these are sticky points within 10 px (borders, then centres, then sizes), never smaller than the minimum size or off the canvas, and the lines disappear on release | G |
| SQ-35 | Any number of Claude, Codex and GitHub accounts: extra accounts (a home folder or `gh` config folder, no secret stored) are read by their own workers, keep their own usage, tokens, sessions, activity and health, are chosen per widget (`claude:work`), and an unknown account is shown as unknown, never as another account's value; configurations without accounts still load | G |
| SQ-36 | Runs on any Linux distribution and on Windows 10 and 11: no KDE, systemd, NVIDIA or fixed-folder assumption in portable code; Linux hosts (layer-shell, X11) are Linux-only, Windows is an ordinary window; the collector link is a private socket (Unix) or a token-checked loopback port (Windows); state, program and login startup live in the platform's own per-user folders; CPU and memory are read through Windows APIs and every GPU, of any vendor, through the Windows GPU performance counters (NVIDIA also through `nvidia-smi` for temperature and power); unknown values are never invented; the Windows build is compiled and tested in a real Windows 10 and Windows 11 machine | G |
| SQ-37 | Wallpaper colours: a Customize option (global and per widget, off by default, kept in the validated configuration) makes the widget palette follow the wallpaper: a pure function turns sampled wallpaper pixels into one hue seed (greyscale wallpapers give no hue, never an invented one), the palette for the dark or light mode is built from it with readable contrast (text 7:1, muted, accent, warning and error 4.5:1 against the background), the host finds the current wallpaper on KDE, GNOME and its derivatives, XFCE, LXQt/LXDE, feh/nitrogen, hyprpaper, an explicit `STATUS_QUO_WALLPAPER` file and Windows 10/11, re-reads it when it changes, and when the wallpaper cannot be found or decoded the configured palette stays in use and the reason is shown next to the option; while the option is on, the colour swatches of Customize show the colours actually applied | G |
| SQ-38 | Session progress is found by Status Quo itself: the done/total steps and current step of a session are rebuilt from its own transcript (Claude `TaskCreate`/`TaskUpdate`/`TodoWrite`, Codex `update_plan`), a repeated transcript line counts once, an unknown task id or missing list gives no progress (never 0/0), and the `codex-pbar` progress folder is only an optional extra whose absence is no fault, no health entry and no notice | G |
| SQ-39 | Every source path (Claude, Codex, workflow-memory and optional progress folders, account home folders, project roots) can be chosen with a built-in folder navigator in Customize: Browse opens a window showing the current folder with Up, Home and drive/root buttons, subfolders to click, a plain-language explanation and Use this folder / Cancel; the tray stays free of file access (the host supplies listings), chosen paths are stored as `~/...` inside the home folder, an unreadable folder shows the reason, and a host without file access (browser sample) hides Browse | G |
| SQ-40 | User tutorial: the README is a guided tour (big picture, install on Linux and Windows, first minute, widgets, accounts, customization, building a widget, troubleshooting) linked to guide pages and a styled page `docs/index.html`; every relative link in them resolves, every registered widget kind and every `STATUS_QUO_*` variable it names is documented and exists in the code, and the widget code printed in the guide is the code compiled by a test | G |
| SQ-41 | One-step installation and compatibility check: `status-quo doctor` (every platform) reports in plain words whether this computer can run Status Quo, what optional data is missing and how to fix it, and exits non-zero only for a blocking problem; `tools/install.sh` pipelines the whole Linux process (computer check, build libraries for apt, dnf, pacman and zypper families with sudo only for packages, Rust through rustup, source, build, per-user install, start, doctor) with `--check-only`, `--dry-run`, `--uninstall`, `--yes` and `--no-deps`; the one-file `status-quo-setup.exe` (CI artifact and release asset) carries the program, checks Windows 10 or 11, installs for the user without administrator rights, starts it, runs doctor and can uninstall; both are described in the README and install guide | G |
| SQ-42 | Adopting an unmanaged installation: when a file Status Quo manages (the program, service units, desktop entries) already exists with content it did not install, `status-quo install` still refuses and leaves it untouched, and `status-quo install --adopt` first keeps that content as a backup named `<file>.before-status-quo` (an existing backup is never overwritten), then takes ownership so later installs and uninstall work; assistant hook files are never adopted; `tools/install.sh --adopt` passes the option and the refusal message names it | G |
| SQ-43 | The project is open source under the MIT License: the `LICENSE` file is the MIT text, every crate inherits `license = "MIT"` from the workspace, the README links the license, and every third-party GitHub Action in the workflows is pinned to a full commit SHA | G |
| SQ-44 | Chart heights in a widget are computed from the room left after its text lines and the gaps between all its lines (never below 34 px), so a widget with several charts, such as a two-GPU system, fits its box instead of overflowing and clipping its first line | G |
